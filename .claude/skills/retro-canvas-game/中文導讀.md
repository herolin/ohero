# 中文導讀 — `retro-canvas-game` skill

這份是給**你自己看的**摘要。`SKILL.md` 和 `references/` 是寫給 Claude 執行用的,所以用英文
(觸發準確度和遵循度比較好,也和程式碼註解一致)。這裡說明它收了什麼、為什麼收。

## 這個 skill 是什麼

把 g001–g008 累積下來的做法收成一份可重複使用的指令。下次開 g009,或者叫 Claude 改任何一個
現有遊戲,它會先讀這份,而不是從頭重新踩一次同樣的坑。

**它不是文件摘要,是「不要再犯」的清單。** 裡面每一條幾乎都對應一個真實付出過代價的事件,
而且都帶著當時量到的數字 —— 因為沒有數字的經驗,下一個人(或下一個 Claude)沒有理由相信。

    ├── balance.md                    量測平衡:機器人、技能落差、兩個陷阱

Claude 平常只載入 `SKILL.md`(不到 500 行),需要哪一份才去讀哪一份 —— 這是 skill 的
標準做法,避免每次都把幾千行灌進上下文。

## 為什麼 `simulation-and-view.md` 是核心

因為那是我們花最多輪、最久才找到的一類問題,而且四個症狀完全不像同一個原因:

| 回饋 | 真正的原因 | 量到的數字 |
|---|---|---|
| 「三個消掉但沒特效,就這樣不見」 | 畫面用**整次按下之前**的一張快照查食材 | 49.6% 的格子畫成錯的食材 |
| 「只吃一個為什麼整盤都亂掉」 | 畫面畫的是**整局結算完**的盤面 | 有連鎖的按下平均 37% 的格子是未來的 |
| 「第一個消除的特效在別的格子」 | 畫面自己去猜「現在是哪一步」,而它猜的是上一步 | 第一次消除完全不閃;之後只閃 0–2 格 |
| 「還是看不到消除」(前面都改過了) | 沒人量過特效在畫面上停幾毫秒 | Combo 4 之後線只亮 **62ms**(四格畫面) |

共同的一句話寫在那份檔案裡:**模型一次把整件事結算完的話,每一個要畫的東西都必須被告知
它屬於哪一個瞬間 —— 畫面層永遠不可以自己從共用狀態推斷「現在」。**

這一條收進 skill 的價值最高,因為它**看起來像特效問題,但改特效永遠修不好**,
而三輪下來我們正是那樣繞的。

## 另外幾件收進去的事

- **平衡要量,不能靠感覺。** 重點指標是**技能落差**(認真玩 vs 亂按)。這個專案發生過兩次
  「認真玩不比亂按高分」—— 那代表玩家唯一的操作是裝飾品,再怎麼打磨都沒用。
  也收了兩個陷阱:機器人用絕對門檻會自己推翻結論(要用百分位),以及 **12 個 seed 是雜訊**
  (12 個 seed 量到的排名,在 60 個 seed 下反過來)。
- **一整套綠色的測試不代表什麼。** 293 個測試在三個玩家看得到的 bug 面前全綠。所以收了
  「反向驗證」這個習慣,以及**四種假測試的長相** —— 包含「跟程式碼讀同一個常數」、
  「只要求有一個特效存在」(零星錯誤的特效就滿足了)。
- **jsdom 的 canvas stub 一定要記錄畫了什麼。** 吞掉繪圖呼叫的 stub,就是最嚴重那個 bug
  通過全套測試的原因。
- **不要在玩家已經按下之後才生出障礙。** 冰在盤上是規則(看得到、可以繞);
  補位把冰**發進一條剛湊好的線裡**是不可學習的,那才是 bug。
  分成 24% / 8% 之後,一個回饋變成一個精準的修正 + 一個可讀性修正,而機制留著。
- **改了規則要去找所有「描述那條規則」的地方。** 有一次改完星星規則,開始頁三個語系還在教
  舊規則 —— 玩家唯一查規則的地方,寫的跟遊戲做的相反。

## 怎麼用它

**安裝到你的帳號(建議)。** 我會另外打包成一個 `.skill` 檔傳給你,點「Save skill」
就會裝進你的個人設定,之後**在任何 repo 裡都會生效** —— 包含還不存在的 g009。

**留在 ohero 裡。** 這份原始檔提交在 `ohero` 的 `.claude/skills/`,所以它有版本歷史、
可以跟著專案一起演進。但**只有在 ohero 這個 repo 裡工作時**才會自動生效,
所以它主要是「正本」,日常靠上面那個安裝方式。

**要改它的時候。** 直接改 `ohero` 裡的檔案,提交。如果改動有份量,順手更新這份中文導讀。

## 一個誠實的說明

這個 skill 我沒有跑 skill-creator 的測試循環驗證(你選了先看草稿)。也就是說:內容我確認過
每一條都對應真實事件和真實數字,但**「Claude 讀了它會不會真的照做」還沒有實測過**。

要驗的話是這樣:出幾個測試題(例如「幫 g008 加一個新特效」),分別讓有 skill 和沒 skill 的
Claude 各做一次,再比對結果。跟我說一聲就可以跑。
